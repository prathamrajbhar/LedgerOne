# Project Type Picker

Determine the correct format for any deliverable before jumping into implementation:
**Web Application · Wireframe · Interactive Prototype · Diagram · Software Architecture Doc · HTML Email · Presentation Slides · Style Guide (Color + Type) · Document/Report**

## Selection Rules

1. **Production Code / Functional UI → Web Application**: Interactive, responsive, multi-page application interface. Standard choice for implementing real product features.
2. **Structural Discovery & Layout Planning → Wireframe**: Low-fidelity layout planning to resolve hierarchy, navigation, and content placement before styling.
3. **Flow Testing & User Research → Interactive Prototype**: Focused mockup of a specific user flow before engineering backend integrations.
4. **Systems, Architecture & Data Modeling → Diagram**: Sequence diagrams, ERDs, cloud infrastructure, or state-machine flows.
5. **API & Engineering Specifications → Software Architecture Doc**: Detailed specification covering data contracts, error models, and integration points.
6. **Transactional & Lifecycle Messaging → HTML Email**: Responsive, cross-client email templates (e.g. React Email, MJML, inline HTML).
7. **Investor, Client, or Stakeholder Demos → Presentation Slides**: Slide decks for project overviews, feature showcases, or final pitches.
8. **Brand Foundations & Tokens → Style Guide (Color + Type)**: Establishing palettes, scales, and tokens before building UI components.

## Output Format

```
TYPE:   <Selected Deliverable Type>
WHY:    <One line explaining fit for this specific requirement>
NEXT:   <Next immediate step or associated skill, e.g. design-standards or generic-crud>
```
